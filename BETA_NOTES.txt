BiliSub Studio v4.0.0-beta.12 RC13-HF7 — HEVC DIRECT-PLAYBACK PROBE WINDOWS TEST
=====================================================================

RC13-HF7 HEVC DIRECT-PLAYBACK HOTFIX
- Fix Windows field regression where OCR source video preview/timeline was valid but `Phát` and `Bật tiếng` could remain disabled while no scan was running.
- Root cause: `ocrSyncControls()` used transient decoded-frame readiness (`readyState >= 2`) as the persistent Play/Mute eligibility gate. Seek/checkpoint refresh could observe a temporary non-ready frame and leave controls stuck disabled.
- Direct browser playback now uses `ocrDirectPlaybackReady`: valid preview metadata + active `/api/media` source + non-fallback mode.
- Direct Play/Mute are available whenever OCR is idle; Scrub remains available from preview metadata.
- FFmpeg JPEG fallback still disables Play/Mute and keeps Scrub available.
- Active OCR scan still disables Play/Mute/Scrub while backend scan owns preview time.
- Play/pause/seeked events resynchronize both player labels and enabled/disabled control state.
- Browser E2E includes a regression that forces frame-ready false on a valid direct source and verifies Play/Mute do not stick disabled.
- No OCR model, threshold, tracker, Chinese-only validator, parallel scan, Auto resource gate, checkpoint, NVDEC, or SRT change.


RC13 replaces RC12 request-level GPU micro-batching as the primary full-video performance strategy.


RC13-HF5 CHINESE-ONLY OUTPUT / MANUAL QC HOTFIX
---------------------------------------------------
- Chinese OCR scan output now has one strict contract: every emitted cue must contain at least one Han ideograph and must not contain letters from another script. Foreign OCR garbage such as ILLC, AIYI, 2/, mixed `铺 U 碎`, Latin/Kana/Hangul-only text, and similar artifacts are discarded as inconclusive samples.
- Digits/punctuation/symbols remain allowed when the cue also contains Han text (for example 第3集). Foreign-script samples are NOT treated as empty frames, so they cannot prematurely close a real active Chinese cue.
- `NormalizeChineseSubtitleText` is applied at tracker Observe, checkpoint Restore/commit, parallel boundary reconciliation, and once again in `/api/ocr/export` before SRT numbering. Old checkpoint/frontend state therefore cannot reintroduce non-Chinese cue text into the Chinese SRT.
- Repeated spaced punctuation artifacts such as `， ，` are normalized before commit/export.
- Live polling remains bounded to at most 120 nearby cues for performance, but a completed scan now renders the complete cue list instead of truncating the UI to the last 120 rows. The UI explicitly shows `displayed / total` cue counts.
- When the user seeks/scrubs the source-video timeline after scan completion, the subtitle list automatically highlights and scrolls to the cue nearest that timestamp. Clicking a cue seeks the source preview back to that cue.
- The right-side labels are clarified as `Phụ đề gần nhất`, `Tổng phụ đề đã ghi nhận`, and `Danh sách phụ đề`.
- No OCR model/threshold, detector, parallel segment topology, Auto resource gate, NVDEC, checkpoint durability, Pause/Resume timing, or boundary ownership rule changed.

RC13-HF4 PARALLEL TELEMETRY / PAUSE UI HOTFIX
------------------------------------------------
- Fix paused schema-4 checkpoint UI reporting stale active lanes from the last live poll. A paused checkpoint now reports 0 active lanes.
- Fix parallel checkpoint progress: the progress bar/percentage now uses aggregate unique core work across every lane instead of incorrectly reusing only the contiguous preview frontier. The contiguous frontier is still shown separately as the safe preview timestamp.
- Fix live/checkpoint cue list mismatch where preview could be near the beginning while the list showed far-future cues from another lane. The displayed recent cue window is now bounded to the contiguous preview frontier; total cue count still includes all reconciled lane cues.
- Parallel live telemetry now supplies cue_count, boundary merges, visual confirmations, cumulative FFmpeg wait/visual-analysis timing, OCR/cue and confidence/text aligned with the preview frontier.
- Remove the full global cue array from every ~450 ms parallel live poll. Full cues remain available at final completion/export, reducing growing JSON/UI overhead on long scans without changing SRT output.
- Rename the two cumulative timing labels to "Tổng chờ FFmpeg" and "Tổng phân tích ảnh" so they are not mistaken for instantaneous latency.
- No subtitleTracker rule, A/N/W/OV guard, OCR threshold, detector/model, segment topology, Auto resource gate, checkpoint durability or SRT final-output semantics changed.

RC13-HF3 SUBTITLE CORRECTNESS HOTFIX
------------------------------------
- Fix repeated standalone Latin OCR garbage such as A, N, W and OV becoming subtitle cues after enough confirmations.
- Standalone 1-3 Latin letters are now treated as inconclusive OCR noise in the Chinese OCR export path; they do NOT act as empty frames and therefore do not close a real Chinese cue.
- Restored schema-3/schema-4 tracker state is cleaned so old A/N/W/OV cues cannot survive Resume.
- The parallel boundary reconciler applies the same final-output guard to stale lane cues from older checkpoints.
- Historical HF3 behavior preserved numeric-only/mixed/long-Latin text; HF5 supersedes that rule with a strict Chinese-only output validator.
- No OCR threshold, detector/model, Auto resource gate, NVDEC, parallel topology, checkpoint schema or Pause/Resume semantics changed.

RC13-HF2 AUTO RESOURCE PREFLIGHT
--------------------------------
- Auto now uses Predict -> Probe -> Commit before every increase 1 -> 2 -> 4 -> 8 -> 16.
- The next level is NOT spawned until the previous real-video benchmark has supplied resource telemetry and the preflight gate passes.
- Windows production builds sample native system RAM + CPU through kernel32 and NVIDIA VRAM + GPU utilization through the existing nvidia-smi driver tool. No Python/pip/CUDA SDK install is required.
- RAM/VRAM safety checks use the measured baseline plus the previous level's worst memory headroom to predict the next level before creating more workers/FFmpeg lanes.
- CPU/GPU pressure can stop Auto before expansion; resource telemetry that is unavailable does not guess that the machine is safe, but falls back to HF1's bounded benchmark watchdog.
- Safety margins: at least 2 GiB or 15% system RAM (whichever is larger) and at least 768 MiB or 18% VRAM (whichever is larger) are preserved during Auto prediction.
- Average benchmark CPU/GPU load is used for saturation decisions so a single short utilization spike does not falsely cap Auto.
- HF1 hard per-level benchmark timeout, bounded pool expansion/restore, cancellation and hard-reset recovery remain active as the second safety layer.
- New Auto stop reasons include cpu_pressure, gpu_pressure, ram_guard and vram_guard.
- No subtitleTracker, OCR threshold, detector/model, checkpoint schema or manual 1/2/4/8/16 semantics changed.

RC13-HF1 FIELD HOTFIX
---------------------
- Fix Windows field-test hang where Auto could remain forever at "Đang đo 16 luồng quét OCR..." after system load had already fallen back near idle.
- Every Auto benchmark level now has a hard 15-second measurement deadline.
- Auto worker-pool expansion is bounded; a stalled worker startup cannot block calibration forever.
- A timed-out high level is canceled and Auto falls back to the last completed lower level instead of waiting indefinitely.
- Restoring the last known-good OCR worker pool is also bounded. If a canceled worker refuses to drain, the managed OCR worker pool is hard-reset and rebuilt at the last known-good size.
- These changes do not alter subtitleTracker rules, OCR thresholds, segment ownership, checkpoint schema, PaddleOCR models, detector, or manual parallel scan semantics.
The OCR recognition stack itself stays unchanged:
- PaddleOCR 3.7.0
- PaddlePaddle 3.2.x private runtime
- PP-OCRv6_small_det + PP-OCRv6_small_rec
- detector remains enabled
- Auto / GPU / CPU / CPU+GPU device choices remain available
- NVIDIA NVDEC path from RC11 remains available per scan lane

WHY RC13
- Real Windows RC12 field evidence showed Batch 1 around 5.5x realtime and Batch 4 around 5.6x on the same test machine/video path, while Batch 4 averaged about 2.86 images per request.
- Request coalescing therefore did not provide enough end-to-end throughput gain to justify treating it as the main performance strategy.

PARALLEL SEGMENT SCAN
- OCR scan UI is now "Luồng quét OCR": Auto / 1 / 2 / 4 / 8 / 16.
- N means N real timeline scan lanes, not N images collected into one request.
- The video timeline is partitioned into deterministic non-overlapping core ranges.
- Each lane receives bounded pre/post overlap only for tracker context and boundary completion.
- Each lane launches its own bounded FFmpeg range with -ss + -t and keeps the existing NVDEC/software fallback path.
- Each lane owns its own sparse visual gate and subtitleTracker. Tracker state is never shared concurrently.

SHARED OCR WORKER POOL
- Scan lanes feed one shared work-conserving PaddleOCR worker pool.
- GPU mode can temporarily expand from the primary worker to multiple private GPU workers.
- A full pool applies backpressure; OCR candidates are not dropped.
- Hybrid remains GPU-first and the CPU helper is deliberately limited.
- Worker startup waits for the existing READY/model/device handshake before a worker enters the pool.
- After a scan the pool shrinks back toward the normal primary-worker footprint.

AUTO
- Auto is not hard-coded to a GPU model name.
- It measures the current level on short end-to-end windows from the real source video, records CPU/RAM/GPU/VRAM resource telemetry, and runs a preflight safety prediction BEFORE creating the next 1 -> 2 -> 4 -> 8 -> 16 level.
- It stops when the next level is predicted to violate RAM/VRAM safety margin, current CPU/GPU load is already saturated, the next level gives less than 10% additional throughput, worker capacity fails, or the video is too short.
- If resource telemetry cannot be read, Auto falls back to the bounded HF1 benchmark watchdog instead of assuming the machine can safely scale.
- The selected topology is then locked for the scan and for Resume; RC13 does not dynamically repartition a paused scan.
- Manual requests are not silently downgraded for an undersized video/resource failure; an explicit error is returned instead.

BOUNDARY CORRECTNESS
- Cue ownership is based on cue start inside a lane's core range.
- Overlap is context, not duplicated output ownership.
- Final cues are globally timestamp-sorted and conservatively reconciled around segment boundaries.
- Completion order of parallel lanes must not change final subtitle ordering.
- Existing sparse visual confirmation is retained; standalone 1-3 Latin A/N/W/OV-style noise protection is strengthened in HF3 without changing OCR thresholds or detector/model behavior.

PAUSE / RESUME
- New parallel scans use checkpoint schema 4.
- Schema 4 stores selected topology and per-lane media/cues/active tracker state/frames/cumulative telemetry.
- Pause is a global barrier: every active lane must reach its own tracker-safe checkpoint boundary before the schema-4 checkpoint is fsynced and the job is reported PAUSED.
- Reopening the app and Resume keeps the saved topology; completed lanes are not rescanned.
- Valid RC12 schema-3 checkpoints remain resumable through the legacy one-lane path so existing progress is not discarded.
- Quét lại từ đầu removes the matching schema-4 and legacy schema-3 checkpoint.

TELEMETRY / UI
- Selected lanes
- Active lanes
- Completed lanes
- Boundary merges
- OCR images / inference calls
- Realtime speed based on unique core seconds (overlap is not double-counted)
- Decoder / visual-confirmation metrics remain available

LEGACY RC12 BATCH PATH
- The RC12 JSON batch transport and schema-3 single-timeline code are retained only for compatibility/resume.
- New RC13 UI scans force request batch 1 inside each lane so "2/4/8/16" has one unambiguous meaning: real parallel scan lanes.

GOOGLE DRIVE

RC13-HF7 HEVC DIRECT-PLAYBACK CORRECTION
- MP4/M4V/MOV HEVC/H.265 is no longer rejected before the browser gets a chance to decode it.
- Shared preview now treats HEVC in the MP4 family as a direct-playback candidate, exactly like H.264/AV1.
- The existing <video> error handler remains the authority: if Windows/Chromium cannot decode that concrete HEVC file, preview falls back to FFmpeg frame mode.
- This enables real Play/Mute on HEVC-capable Windows systems instead of keeping the buttons permanently disabled merely because ffprobe reported codec=hevc.
