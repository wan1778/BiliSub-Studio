# BiliSub Studio engineering guardrails

These rules apply to the current **C# + .NET 10 + WinUI 3** production tree.

## Source of truth

1. Runtime behavior is defined by the current source and tests, not chat history, old binaries or deleted legacy code.
2. `ARCHITECTURE.md` defines current ownership boundaries. Source wins if docs drift, and docs must be corrected in the same change.
3. `docs/migration/CSHARP_CODE_MAP.generated.md` is generated by `csharp/scripts/generate_csharp_code_map.py`; never hand-edit it.
4. Do not patch release binaries. Fix source, add/adjust regression coverage, build, verify and publish a new beta/stable release.
5. Legacy Go implementation is history-only and must not be reintroduced into the production tree or build.

## Production ownership

- `csharp/src/BiliSubStudio.App` — WinUI shell/pages, visual state, pickers and application startup.
- `csharp/src/BiliSubStudio.Core` — application/core services, jobs, config, media, video, subtitle, OCR, editor, auth and maintenance.
- `csharp/src/BiliSubStudio.Launcher` — user-visible root launcher only; it starts `Runtime\BiliSubStudio.exe` and must not implement feature logic.
- `csharp/tests` — Core/transport regression executables.
- `csharp/installer` and `csharp/scripts` — verified Windows packaging and release gates.
- `internal/ocr/worker.py` — private Python PaddleOCR worker asset embedded and checksum-verified by the C# build.

## Hard prohibitions

- No Go production source or Go build path.
- No second BiliSub backend process or fixed secondary HTTP port.
- No `BiliSubStudioCore.exe`.
- No localhost/browser/WebView/WebView2 production UI.
- No deleting completed/recoverable download state after a network error or cancellation.
- No accepting incomplete/oversized Range bodies as completed data.
- No changing downloader concurrency, segment size, CDN rotation, resume semantics and fallback behavior together without targeted tests for each affected contract.
- No CDN hostname invention. Bilibili failover candidates must come from actual playurl `baseUrl + backupUrl[]` data for the selected format.
- No splicing a refetched stream into existing partial bytes if format ID or expected stream size changed.
- No treating a Python executable/model directory alone as a healthy OCR install; the managed runtime, manifest and worker identity must agree.

## Mandatory workflow for non-trivial changes

1. Pin the current commit/branch.
2. Map the call path and direct owners affected by the change.
3. Read the current implementation and its existing regression coverage.
4. Define the failure/regression scenario before or with the fix.
5. Make the smallest scoped source change.
6. Run targeted contracts first, then the full Windows verification gate.
7. Regenerate/check the C# code map.
8. Do not call a field defect fixed until the exact new build passes the relevant real-machine scenario.

## Windows verification

From repository root:

```powershell
powershell -ExecutionPolicy Bypass -File csharp/scripts/verify.ps1
powershell -ExecutionPolicy Bypass -File csharp/scripts/package_windows_candidate.ps1
```

CI additionally runs:

- long-media/media-bundle static contracts;
- raw Bilibili primary/backup CDN discovery regression;
- exact Range-offset CDN failover regression;
- root-launcher/tidy installer layout contract;
- C# build/Core contracts/Range regressions;
- real WinUI startup/layout smoke;
- installer install/migration/root-launch/uninstall smoke.

Any relevant gate failure blocks that build.

## UI/UX contract

- Top-level navigation stays focused: Media, OCR, Editor, Settings.
- Performance, Login and Update/Support live inside Settings rather than becoming extra top-level pages.
- Logging is application-wide, not one isolated log per feature page.
- Media layout should use available horizontal space and keep source/content/quality/output/progress hierarchy clear.
- Visual changes must not alter feature ownership or transport/OCR behavior unless explicitly planned and tested.

## Release policy

- Public beta may ship after automated Windows/build/installer gates pass while field QA continues.
- Stable `4.0.0` is a separate quality gate.
- A published beta version is immutable: cleanup-only commits must not overwrite its release assets. Functional fixes require a new beta version.
- `update/beta.json` and `update/stable.json` must point only to verified GitHub Release payloads with exact SHA-256 and size metadata.
